Timed Audit Mode

Move selected agents from one Airlock policy group (usually enforcement) into another (usually audit mode) for a set amount of time, then move them back automatically — even if the app was restarted while the timer was running. Uses your Airlock Digital API key and tenant from Settings.

Note: app.py needs to keep running for scheduled reverts to happen automatically. If it's closed while a timer is running, the revert catches up as soon as you start it again — it won't happen while it's off.

ISO 27001 Compliance Assessment

Shows how each Airlock policy group's configuration provides evidence toward specific ISO/IEC 27001:2022 Annex A controls. This covers only the subset of controls an application-control product can speak to directly — it's a starting point for a broader audit, not a certification on its own. The control list below is editable in iso_mapping.json.

VirusTotal API

Add your VirusTotal API key to enable uploading compiled .exe files for scanning. Get a free key from your VirusTotal account settings. The key is stored in a local config.json file next to app.py — plaintext, on your machine only.

Airlock API Settings

Save multiple Airlock connections — each API key is stored together with its own tenant and port as one unit, so you can't accidentally point the wrong key at the wrong server. Scripts you run from the Scripts tab can read the active connection via AIRLOCK_API_KEY, AIRLOCK_TENANT, and AIRLOCK_PORT (your VirusTotal key is also available, as VT_API_KEY).

GitHub sync

Optionally sync .py files from a GitHub repo into the script folder above. Sync runs automatically on startup when enabled, and can be triggered manually any time. Other files already in the folder are left untouched.

Publish to GitHub

Pushes this app's own source files — not your data — to a GitHub repo of your choice, as a single commit. This is separate from GitHub sync above, which pulls scripts the other direction; publishing can use the same repo or a different one entirely.

Always includes exactly these files, nothing else — config.json, cloud_config.json, venv/, and everything else your .gitignore already excludes are never touched:

.gitignore, app.py, iso_mapping.json, PROJECT_SUMMARY.md, README.md, requirements.txt, run.bat, templates/index.html

Logging

When enabled, this covers everything currently printed to the terminal running app.py — including diagnosing third-party API calls (Airlock Digital, VirusTotal, GitHub, the Cloud multi-tenant API) — and also writes it to app.log next to app.py, so it's not lost when the terminal window closes or scrolls back too far. The log file rotates automatically once it gets large, keeping a few backups. Takes effect immediately, no restart needed.
